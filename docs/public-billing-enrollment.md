## Scope and trust
BILLING_PUBLIC_ENROLLMENT_ENABLED defaults OFF in BOTH landing and Base44 for new signups. Previously enrolled customers remain recognized when it is OFF. Existing pilot config remains a valid fallback. ON is not a wildcard: only newly created Google-verified, S2S-authorized organization/member pairs receive a server registry entry and membership provenance.

createOrganizationForUser registers the newly returned member ID, org ID, verified Google sub and owner role via SET NX only after creation. Does not retroactively mint trust when returning already_exists. Missing/conflicting/unknown outcomes retain the existing creation lock and fail; operator must reconcile exact created rows/proof before further attempts. No entity writes may be done from a browser. Old onboarding ensureUserOrganization and old rows are not auto-enrolled; no matching by email. The helper cannot be exposed as a public function or called on arbitrary preexisting rows.

Registry: trucky:billing:enrollment:v1:org:<id> = {version:1,orgId,memberId,googleSub,role:'owner'}. Proof: existing trucky:billing:member:v1:<org>:<sub> with exact expected format. No trial/subscription data or tokens in those records. One EVAL validates conflicts before a single MSET writes both records. A lost response or historical partial pair remains blocked for operator review, not duplicated or automatically trusted. Re-running helper is safe only on the exact known newly-created pair after review. Never clear or remint identity/checkout trust keys blindly.

Resolver returns billing_public_enrollment only for matching current owner membership/sub+registry, separately from demo eligibility. Backend eligibility, direct/native link, handoff redemption and live sync add only the exact registered pair to the request's scope. They retain all existing membership/provenance/bidirectional native checks, quotas, Stripe price/customer/metadata checks, sync locks and unknown-write handling. Legacy pilot membership is unchanged. General sync cannot accept arbitrary metadata.org_id without its server enrollment. Direct link still verifies signed Google ownership and native session; resume still requires confirmation and exact bidirectional mapping.

Landing must be updated with the companion PR: general flag allows a request to reach backend checks; it does not override their verdict. New unlinked owners see LIVE_IDENTITY_LINK_REQUIRED before payment, navigate to /billing-link and confirm with their own native Base44 session. Return to landing, choose same company/plan and only then checkout. This intentionally requires account confirmation BEFORE charging. Existing native signup/onboarding may create a separate company: verify canonical company selection after linking, not just email login. Multi-company ambiguous resumes remain blocked, not auto-selected.

## Review correction: reuse, not a replacement billing architecture
The existing Google, Checkout, webhook, member linking and DemoTrial flows are reused. BILLING_PUBLIC_ENROLLMENT_ENABLED gates NEW creation only. readEnrollment/expandedScope recognize previously registered pairs regardless of that flag, so a pause of signups does not block their later linking/sync/cancellation/impayment handling. Native and live sync flags are still independent operational controls. Do not use the signup flag as an emergency webhook kill switch.

Registration now uses one EVAL with exact conflict checks BEFORE one MSET of proof+enrollment. A partial historical pair is rejected for review, not silently completed. Unknown network outcome requires a read/review; exact new-pair registration is idempotent. There are no intermediate proof-only writes in the new script.

New public billing creation uses trucky:billing:create:v1:quota:<sub> and :attempt:<hash>. Quota checked atomically BEFORE acquiring lock; exceeded quota never creates a pending lock. Owner token protected finalization/release. Failures after issuing Organization.create remain uncertain and blocked rather than interpreting any SDK error as no write. Only pre-write failures are eligible for owner-checked cleanup; no automatic deletion of an uncertain attempt. Legacy demo keys/path unchanged when billing enrollment flag OFF.

Existing-account policy: an existing exact Google-owned org with requested name is returned without minting enrollment/provenance. Any other active existing Google membership, same verified-email candidate or owned native organization blocks additional public creation with EXISTING_ORGANIZATION_REQUIRES_VERIFIED_LINK. Email lookup is a duplicate-prevention signal, not authorization. Operator must select canonical org and use the reviewed dual-identity/admin legacy procedure, not create a second company or remint proof. ensureUserOrganization keeps legacy native users unchanged but refuses adopting a server-enrolled company unless its exact active member is linked to the native caller. This does not automate legacy migration and must be exercised with existing/native onboarding before public launch.

Resolver catches corrupt per-org registry, excludes that company and emits a controlled generic warning; other companies still resolve. Backend writes/checkout remain fail closed for the excluded company. If all are excluded the duplicate guard prevents automatic creation from bypassing review.

Acceptance must cover: signup flag OFF still permits recognition/sync for enrolled customers; quota rejection with no pending key; atomic registration conflict/partial/timeout; new owner link then eligibility; existing native account cannot spawn a duplicate; corrupt one-company registry does not hide healthy companies. The patch is staged only. No new general rollout or unrestricted charge is approved by these tests.
