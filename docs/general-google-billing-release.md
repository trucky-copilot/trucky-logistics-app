# General Google accounts — reuse existing flows, remove pilot selection

Base main 03f43ba0480cd885979249cb6cf941278adf2a16. Apply as a new additive PR, NOT on the old v1–v4 working patch. Landing companion is PR #10. This patch changes the source of authorization scope; it does not rebuild OAuth, company creation, Stripe, demo or native confirmation. No production mutations or flags changed by the Agent.

## Authorization for all identities
resolveUserOrganizations, linkBillingIdentity, redeemBillingLink, checkLiveCheckoutEligibility and syncBillingSubscription derive exact org/member scope from current server data plus assertMembershipProvenance. They no longer read BILLING_LINK_PILOT_ORG_IDS/MEMBER_IDS or select a single Google account. Native binding and consent, both directions in Redis, metadata/customer/mode/price checks and persistent uncertainty locks still apply. For user actions a single exact active owner/admin membership for the verified sub is required. For subscription reconciliation use one canonical active owner with proof; ambiguous ownership fails closed rather than picking the first. No email-to-company auto-adoption.

Phase-1 legacy proven membership is already trusted by the same proof checker and need not create another enrollment record to be recognized. New companies still register their pair/proof atomically through the existing server creation path. Missing-proof legacy/native companies continue through the already implemented dual-identity/admin-reviewed existing-company flow; no duplicate organization or fake proof is created to bypass it. General eligibility for every Google user does not entitle any user to another company's billing.

Landing requires the resolver billing_account_verified:true, not a hardcoded subject or org ID. A confirmed verified account gets the same Stripe path whatever its Gmail address (or other Google account with verified email). A not-yet-linked owner must confirm their native account before money collection. Signed Stripe webhook reaches Base44 for every organization; Base44 independently proves membership, native binding and subscription mapping before projecting state. No pilot-only webhook rejects a real customer's cancellation solely for not being Testing-Pro.

## Flags and continuous subscriber processing
BILLING_PUBLIC_ENROLLMENT_ENABLED remains a switch for NEW creation only. Recognition, linking and sync of existing verified memberships do not use that switch. New Checkout remains gated by STRIPE_LIVE_PAYMENTS_ENABLED; stop new sales there, not by deleting proof or disabling existing-subscriber webhooks. STRIPE_WEBHOOK_LIVE_ENABLED and BILLING_SYNC_LIVE_ENABLED must remain consistent for existing renewals/cancellations/impayments. Native link and live eligibility switches retain their current operational meanings. Do not delete Stripe test or managed Upstash variables as part of this patch.

Keep them until one-time legacy consent route /api/billing/legacy-approval is retired/disabled (LEGACY_OWNER_APPROVAL_ENABLED absent/false). Backend new routes no longer read BILLING_LINK_PILOT_ORG_IDS/MEMBER_IDS, but getLiveBilling/checkLinkedLiveSubscription historical diagnostics may still use them; audit before deleting. No automatic deletion here. New signup off must not invalidate ongoing subscriptions.

## General-scope review follow-up
Subscription reconciliation (scope without a user sub) ignores ONLY a row with exact MEMBERSHIP_PROVENANCE_REQUIRED, because an unproven co-owner must not block the sole proven canonical owner. A mismatched/corrupt proof, any other exception or Redis failure aborts: never infer a missing proof from a transport failure. If two owners DO have valid proof, scope remains ambiguous and rejected. User-specific scope without proof returns BILLING_ACCOUNT_REVIEW_REQUIRED; HTTP eligibility maps it to 409, and landing offers the existing-company ownership flow. No trust is minted by returning that code.

Intended activation semantics: BILLING_IDENTITY_LINK_ENABLED=true enables confirmed linking for EVERY active membership with exact server-owned provenance, not just Testing-Pro. It does not authorize arbitrary members, companies or users; wrong native account and unproven legacy membership still fail. This is the requested general-account change. No runtime flags were changed or additional address-specific pilot proposed. Remove unused list parsers from entrypoints; core APIs retain injected exact scope sets to avoid breaking tested policy modules. General collection remains pending canonical-company operational paid access TRUCKY-90 and business approval. Publish initially with STRIPE_LIVE_PAYMENTS_ENABLED=false; keep processing existing-subscriber webhooks.
