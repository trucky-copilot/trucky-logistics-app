Read Stripe LIVE subscription with expanded latest_invoice (REST server-side; key never exposed). Require real mode, exact sub/customer/org metadata, approved USD monthly 29/99 price (quantity 1, per_unit, no extra items), status active with no future trial and latest_invoice real+paid for SAME customer/subscription. Canceled/past_due/incomplete/unpaid/paused/trialing cannot fall back to old test active fields. Historical ended trial is allowed. Cancel-at-period-end with still-active paid subscription remains valid until Stripe changes status. This conservative immediate-deny payment-failure policy has no grace period; business must explicitly approve before enabling. Invoice payment check is provider truth, not just the local status projection.

getMyPlan POST returns managed:false with flag OFF (no Redis/Stripe reads); otherwise authenticates native session and returns only managed/allowed/plan/orgId/code, no invoice/card/tokens. Existing server feature authorization reuses exact same runtime. DemoContext requests this endpoint, uses verified live plan for managed account, rejects wrong active app org, does not grant legacy whitelist/test access on managed denial and refreshes on focus/once per visible minute. Backend rechecks on each protected operation regardless of UI. Endpoint unavailable blocks UI rather than pretending payment success: publish getMyPlan BEFORE frontend.

## Known boundaries — do not claim all TRUCKY-90 complete
This integrates live-plan membership/status/invoice verification and existing feature gates. It does NOT add authoritative volume quotas for trucks/drivers/loads/profiles/monthly documents/chat counts, nor rewrite RLS of every direct client entity. Those limits are still PLAN_LIMITS in the client and must not be described as secure server quotas. Existing marketChat/profile/data authorization and app-wide tenant selection must be reviewed under actual app acceptance, especially profile_id/selectedCarrierId use. Current patch denies ambiguous native/company context rather than implementing a new tenant switcher. Legacy/test subscriptions and test-account exemptions remain existing behavior for unmanaged users, not newly granted live subscriptions. A staged integration isn't a global security guarantee or commercial go-live.

No function here charges cards, mutates org/member/proof/Redis, renews demos or cancels subscriptions. No quotas, provider registry auth, domains or variables deleted. No Vercel deploy necessary for this Base44 patch. Emergency stop new purchases remains STRIPE_LIVE_PAYMENTS_ENABLED=false; do not turn off existing subscribers' webhooks merely to close new sales. Enforcement flag rollback false restores legacy behavior, not an equivalent secure production billing policy; operator/business decides and records rollback.
